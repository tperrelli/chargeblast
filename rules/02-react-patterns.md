# React patterns

- Render collections with `.map()` and stable keys. Do not build JSX arrays with `push` or use `for...of`; prefer declarative data operations when they are clear.
- Format JSX to reveal hierarchy: put opening and closing tags for nested elements on separate lines, and wrap props when an element becomes long. Avoid multiple elements, handlers, or declarations on one line. Do not use compact formatting to satisfy line limits.
- For simple conditions, use `if`, a ternary, or `&&` in a readable way; with `&&` in JSX, use a boolean condition to avoid rendering `0`. Avoid nested ternaries and lengthy markup expressions; name derived values or extract a responsibility when it improves readability.
- Use typed `Record` objects for visual configurations that map known states to labels, colors, or icons. Use normal conditionals for control flow and business rules; do not create artificial lookups to replace every `if`.
- Group related filters and fields into typed state, encapsulated in a hook. Do not use more than three `useState` calls in the same component to control filters or forms. Do not duplicate state that can be derived. Separate selection, filtering, and pagination when they have different responsibilities.
- Keep visual components focused on presentation. Extract selection, export, and state-transition logic when it makes the component difficult to read; short handlers that only forward an event may remain in the component. Avoid excessive props: group only data that forms a cohesive concept, without hiding dependencies in generic objects.
- Do not duplicate behavior such as copying IDs, opening menus, or formatting values. Share implementations when semantics are the same; make different requirements explicit in the interface.
- Use `<details>` only for simple text accordions. For popovers and menus, prefer an existing, reusable accessible primitive. If implementing one, cover focus, Escape, outside clicks, dismissal, focus restoration, semantics, keyboard interaction, and positioning on small screens; do not maintain parallel implementations without a reason.
- Do not use `useEffect` with `setTimeout(..., 0)` to obtain the current time and work around hydration. Receive a serializable timestamp from the server or isolate the update in a dedicated Client Component, keeping the initial render consistent.
- With Cache Components, follow the installed documentation for per-request timestamps: call `connection()` before obtaining the time and place the dynamic content under `<Suspense>`. Calling `Date.now()` directly in a page does not guarantee per-request rendering.
